# CodexWUI for Termux

在手机浏览器中使用本机 Codex：项目与历史会话、流式对话、并行会话、子代理观察、项目文件浏览与上传，以及只读 Git diff。

## 使用

本机已具备 Node.js 和可运行的 `codex`。无需 Ubuntu，无需安装生产依赖。

工作区终端支持 Android Termux 和 Linux，首次使用需要 C 编译器。Termux 可运行 `pkg install clang`。`npm run setup` 会尝试编译终端模块；直接启动时也会在首次新建终端时自动编译。编译失败不影响聊天。

```sh
cd ~/codex
npm run setup
codexwui
```

`npm run setup` 安装 `codexwui` 和同名大小写别名 `CodexWUI`，并移除本项目安装的旧 `CodexWeb` 命令。升级沿用原数据目录、会话和配置；旧 `CODEXWEB_*` 环境变量仍可读取，同时设置时以 `CODEXWUI_*` 为准。

`codexwui` 会后台启动服务并调用 `termux-open-url` 打开 **http://localhost:4310**。再次运行会复用现有服务。

```sh
codexwui --status       # 查看服务与 Codex 连接状态
codexwui --no-open      # 只启动服务
codexwui --stop         # 停止服务，中断任务并将后续消息保留为未发出
codexwui --foreground   # 前台运行，便于查看启动错误
```

也可以用 `npm start` 前台运行。默认只监听 `127.0.0.1`。`PORT=4311 codexwui` 可以更换端口。`CODEX_BIN` 可以指定已有 Codex 启动器，`DATA_DIR` 可以指定项目记录和日志目录。

首次连接本机 Codex 可能需要一段时间；页面上会显示连接状态。需要保持 Termux 后台进程存活。Android 回收 Termux 后，需要重新运行 `codexwui`；本应用不保证系统后台保活。

本机 `codex` 启动器使用 proot 提供 Android 兼容环境。Web 后端会识别已由 proot 跟踪的 Termux 进程，在相应绑定已存在时使用 `codex-native`，避免嵌套 proot 导致新建会话超时；普通 Termux 启动仍使用 `codex`。显式 `CODEX_BIN` 始终优先。

## 界面与行为

- **左栏**：添加已有目录作为项目、按项目浏览历史、分页加载、新建与切换会话。目录支持 `~/…`。历史源于现有 Codex，不只包含 Web 新建的会话。
- **账户额度**：左下角 RAM 右侧显示剩余额度，优先显示 5 小时额度，未提供时显示周额度。点击查看两种额度的剩余百分比和重置时间；缺少的窗口标为“当前账户未提供此项额度”。前台每分钟刷新，支持手动刷新，也接收 Codex 的额度更新通知。按接口返回的窗口时长识别额度，不按套餐名称推断。断线、读取失败或数据过期时显示 `额度 --`。首次更新后，在当前任务结束时执行 `/reload` 加载新增接口。
- **中间**：消息、工具执行过程、审批与输入请求。右上角 `◫` 打开检查面板。手机上左右栏均为抽屉。
- **消息渲染**：主会话、历史、只读子代理和 BTW 共用 Markdown 渲染，支持标题、嵌套列表、表格、引用、代码和链接。数学公式使用本地 KaTeX，支持行内 `\(…\)` / `$…$`、独立公式 `\[…\]` / `$$…$$`；流式内容补齐后自动渲染，无效或不支持的公式保留为原文。宽表格、独立长公式可横向滚动。代码中的公式保持原文，消息中的 HTML 不执行，Markdown 图片展示为可点击链接；已上传图片继续显示缩略图。脚本与字体均从本机加载，无需 CDN。
- **Mermaid 图表**：闭合的 `mermaid` 代码块自动显示为图表，支持流程图、时序图和状态图。主会话、历史、子代理、BTW 和 Markdown 预览共用此功能。流式输出在代码块闭合后渲染，语法错误时展开源码；宽图可横向滚动。渲染器按需从本机加载，在隔离 iframe 中生成 SVG 图片，不依赖 CDN。
- **历史显示**：每个会话初始只渲染最近 5 个 turn，即 5 轮完整交互。向上翻到接近顶部，或点击「加载更早消息」，每次再展开 5 轮；先展开已缓存历史，再请求更早页面。阅读历史时保留位置，新输出不把页面拉到底部。主会话与 BTW 分别保存显示范围和滚动位置，同时输出时各自合并更新正文；其他会话的文字片段不触发当前正文渲染。页面隐藏时暂停界面更新，返回前台后同步进展。显示范围只影响页面，不截断模型上下文。
- **图片**：输入框底部 `▧` 打开手机浏览器的文件选择器；支持 PNG、JPEG、WebP，每条最多 4 张、单张最多 10 MiB。也可粘贴剪贴板图片（取决于浏览器支持），可以只发图片或配文字、技能一起发送，支持引导与排队。选图后先上传到本机，出现缩略图后即可发送，点击 `×` 移除；上传或发送失败保留附件。点击已发送图片可打开原图。切换会话保留各自草稿，刷新页面会丢失未发送草稿。
- **右栏**：文件、终端、子代理、Git diff 与 BTW 标签。子代理显示可获得的名称、角色、状态，运行中的置顶，其余按最近一次运行结束时间从新到旧排列；旧记录缺少结束时间时按最近更新时间排列。状态变化时自动调整顺序，刷新页面后从历史恢复结束时间。支持打开只读会话，顶部“会话”旁的固定按钮可返回父会话；子代理由父会话发起和协调。
- **文件**：以项目为根的逐级目录，包含隐藏文件，文件夹优先排序。点按文件夹进入，点按文件打开原文子标签，同一文件复用标签。支持 UTF-8 原始文本（含 Markdown、JSON、YAML、代码等），普通文件不渲染 HTML/Markdown；StudyCard 生成的 HTML 卡片支持隔离预览和原文切换；可切换换行、复制、手动刷新和关闭标签。切换项目保留各自目录、选中项、文件标签及阅读位置；这些状态保存在当前页面内存，刷新页面会重置。二进制只显示元信息，非 UTF-8 编码提示暂不支持，文本最多预览 1 MiB（截断时复制也仅包含预览）。目录最多显示 5000 项并明确提示；项目内符号链接可打开，指向项目外的链接被拦截。不提供文件编辑。
- **对话文件链接**：点击 agent 发来的本地文件链接，在浏览器新标签页打开预览。支持项目内绝对路径、项目相对路径、`file:///…` 与 `sandbox:/…`；历史消息、子代理和 BTW 使用同一处理。PNG、JPEG、WebP、GIF、SVG 等图片可预览并点击打开原图；Markdown 排版显示（包括公式），可切换原文；代码与其他 UTF-8 文本显示原文，`:行号` / `#L行号` 链接定位并标出该行。Markdown 文件中的相对链接按该文件目录解析。PDF 提供浏览器打开入口，其他二进制或不支持的编码提供下载。文本预览上限为 1 MiB，下载保留完整文件；普通 HTML 显示为原文，StudyCard HTML 使用隔离预览。预览与下载均校验项目边界和同源请求，原文件响应禁用脚本执行。文件不存在或超出当前项目时显示具体原因；外部网址继续按普通链接打开。
- **并行**：不同会话可同时工作；切换或关闭网页不会主动取消任务。同项目共享工作目录，不自动创建 worktree，多个任务可能修改同一文件。
- **连接恢复**：运行中的当前会话长时间没有收到更新时，页面会自动补读最新内容；确认推送落后后重新连接事件流。回到网页前台、恢复窗口焦点或网络上线时也会同步，包括推送断连的情况。后台暂停补读，读取有超时且不会重叠；已加载历史、阅读位置和草稿会保留。
- **Steer**：当前任务运行时，选择“引导”会立即显示预引导卡片，内容先保留在 Web 后端。后端观察到本轮模型响应与工具结果处理结束的边界后，自动向当前 turn 提交；没有固定倒计时。提交前可修改、撤回，也可点“立即引导”主动提交。打开编辑器会暂停该条投递，保存后等下一次边界，取消修改会恢复原内容。文字、图片、技能均会保留。提交后显示“等待 Codex 接收”，收到对应消息回执才合并到正式对话；此时不能撤回。若任务提前结束，保留未提交内容，不会悄悄当作新任务发送。预引导在后端内存中，切换会话、刷新或浏览器断线不丢失；**Web 服务重启会清空**。
- **Follow-up**：运行中选择“排队”，当前任务成功完成后依次发送。失败或停止将待发送消息转为“未发出”；可撤回修改、删除、继续发送一条或继续全部。保存修改不自动发送，附件会保留。新消息不会带出旧的未发出消息。队列持久化在 `queue.json`，服务重启后恢复为未发出；正在投递的消息会提示结果未知，检查历史后再决定是否重发。
- **Git**：查看当前工作区分支、状态、已暂存/未暂存 diff；未跟踪文件只列名称，二进制文件不显示内容。不提供 Git 写操作按钮，可在对话中交给 agent。
- **模型与 reasoning**：输入 `/model` 或点击对话顶部的模型名称，选择当前会话使用的模型和推理强度。模型和支持的强度从本机 Codex 目录读取；切换从下一轮消息生效，包括自动发送的 Follow-up，正在执行的任务与 Steer 保持原设置。未选会话时会先在当前项目创建一个会话。子代理面板仅供查看，不单独修改其模型。
- **权限与登录**：沿用本机 Codex 配置和登录；本应用不会强行开启 full access，也不会把账号凭据交给浏览器。审批按钮只处理 Codex 实际发出的请求。

## 工作区终端

打开工作区面板的“终端”标签，点击“＋ 新建”启动独立的本机 shell。终端属于项目，在项目目录中启动，沿用服务进程的 `SHELL`、环境变量和用户 shell 配置。界面显示的是启动目录；运行 `cd` 后不会把这个标签当作实时路径更新。终端使用 Termux 用户的实际权限，聊天的只读、工作区等 Codex 权限设置不限制手动命令。输入直接进入 shell，不调用模型；输出只保留在服务内存和当前页面，不自动加入聊天，也不写入聊天历史。

同项目切换聊天、切换文件标签、收起面板或关闭网页时，终端继续运行。切换项目显示各自的终端。刷新网页后重新读取该项目的终端列表；当前页面保留各终端的显示内容和选择。每个项目最多同时运行 4 个终端，全局最多 8 个。自然退出的终端可继续查看近期输出，点击“结束”移除记录；正在运行的终端点击“结束”后，确认关闭 shell 及其启动的进程。

停止 CodexWUI 服务、执行 `/reload`、或服务进程退出时，终端及其后台子进程会关闭。重新启动服务后需要新建终端。手动终端不参与 Codex 聊天的空闲清理，开发服务器不会随着聊天结束而被清理。RAM 合计包含手动终端进程，`/api/resources` 的 `manualTerminals` 单列其数量与内存；Codex 的进程和内存保护预算仍管理 Codex 及其派生进程。

终端获得焦点时，外接键盘的 `Tab` 用于补全，方向键浏览历史，`Esc`、`Ctrl+C`、`Ctrl+D` 等按终端语义传递。`Ctrl+C` 中断前台命令；选中输出后可用“复制选中”或 `Ctrl+Shift+C` 复制。底部快捷键栏默认收起，点击“快捷键”展开 `Esc`、`Tab`、`Ctrl`、`Alt`、方向键和 `Ctrl+C`。`Ctrl` 与 `Alt` 高亮后作用于下一次输入，再次点击可取消。栏的展开状态在当前页面中保留。点击“展开”可全屏使用，收起全屏使用独立按钮；`Esc` 始终传给终端。多行粘贴会先显示预览，确认后将原内容交给终端，其中的换行可能执行命令。

连接中断时暂停输入并丢弃尚未发送的按键，不自动重试结果不明的输入。重连按已显示的位置补读，每个终端在服务端最多保留 512 KiB 原始输出，页面保留 3000 行滚动记录。超出保留范围会重置显示并提示较早输出已清理；长时间断线或整页刷新后的全屏交互程序画面可能需要由程序重新绘制。重新收到输出不会抢走聊天焦点。浏览器终端组件按需从本机加载，无 CDN。

## `/` 命令和 `$skills`

输入 `/` 或点击输入框下方 `/` 打开菜单。这些是 Web 客户端明确实现的命令，并非完整 CLI 命令透传。

| 命令 | 功能 |
| --- | --- |
| `/new` | 当前项目新建会话 |
| `/resume` | 打开项目与历史会话侧栏 |
| `/stop` | 等待当前任务及其运行中的子代理停止，再清理后台终端 |
| `/cleanup` | 清理当前空闲会话及子代理的后台终端，并取消订阅；保留历史 |
| `/compact` | 空闲时请求压缩上下文 |
| `/model` | 选择当前会话模型及 reasoning 强度 |
| `/config` | 动态调整全局限制、新会话默认模型与文件展开形式 |
| `/skills` | 打开技能选择菜单 |
| `/plugin` | 查看已安装插件并切换全局开关（也支持 `/plugins`） |
| `/StudyCard` | 开启当前会话的知识卡片自动归档 |
| `/StudyCard --stop` | 关闭归档，下一轮注入一次关闭提示 |
| `/StudyCard --status` | 查看归档开关和保存目录 |
| `/status` | 查看当前会话状态、项目、模型、运行会话数及进程/内存预算 |
| `/files` | 打开项目目录与原文文件标签 |
| `/agents` | 打开子代理面板 |
| `/diff` | 打开 Git diff 面板 |
| `/help` | 查看简要帮助 |

点击 `/` 按钮会在草稿上方补一行 `/`，保留原有正文、技能和附件；已存在命令行时不会重复插入。操作命令放在第一行，例如 `/config`，执行或从候选项选中后只移除这一行，下面的草稿保留，不发送给模型。执行失败时恢复命令；执行期间新写的文字不会被清空。`/new` 切换到空白会话，原会话的草稿仍可切回继续；打开模型设置或开启 StudyCard 所需的首次建会话会带入未发送草稿。

输入 `/技能名` 可以搜索当前项目的技能，候选项显示为 `/skill：技能名`。点击后将命令行替换为 `$技能名` 并添加技能标签，下面的正文保留。输入 `$` 或点击 `$` 按钮也可选择技能；直接发送 `/skill: name 任务描述`、`/name 任务描述` 或 `$name 任务描述` 都会将技能与任务一起发送，引导和排队消息同样支持。`/skill：name` 的中文冒号也可用。技能与内置命令重名时，`/name` 优先执行内置命令，可用 `/skill: name`、`$name` 或从技能候选项选择来调用技能。同名技能有多个来源时需要通过菜单选定。点击技能标签可以移除选择及正文中的引用。

`/plugin` 打开已安装插件列表，可筛选、重新读取并切换开关。开关通过 Codex 的配置接口保存到本机 Codex 全局配置，共用该配置的 CLI 等客户端也会受影响；新建会话使用新配置，已有会话可能保留已加载的技能和工具。切换后刷新技能菜单，受账号或管理员策略限制的插件显示原因且不能切换。配置被其他页面或客户端修改时，需要重新读取后再操作。BTW 侧聊禁用插件。此面板依赖本机 Codex 的 `plugin/installed` 接口；安装、卸载仍在终端使用 `codex plugin` 命令。

手机输入回车换行，点击按钮发送；外接键盘支持 `Ctrl+Enter` / `Cmd+Enter`。

### StudyCard 知识卡片

输入 `/StudyCard` 为当前会话开启自动归档，首次开启会创建项目内的 `StudyCard/`。命令大小写不敏感，重复执行保持开启；没有选中会话时会先新建一个会话。开关和最近的保存结果保存在 Web 数据目录的 `studycards.json`，刷新网页、恢复会话或重启 Web 服务后保留；其他会话、子代理与 BTW 侧聊独立，不会自动开启。

开启后，Web 后端在每轮实际发送时附加归档规则和当前 `StudyCard/` 目录树。agent 判断是否准备进行实质性的知识讲解：需要归档时，先用单独一行输出 `StudyCard: Python语法/容器/list/切片`，再讲解或调用可视化工具；普通闲聊等不加归档头。归档头可以位于中间回答或最终回答中，也可以独占一条消息。目录提示要求同一概念尽量复用已有名称，避免同义词或中英文产生重复分类；旧 Markdown 和新 HTML 卡片都会列入目录树。目录树最多列出 300 项、12 层、约 12000 字符，过大时明确标记截断；不跟随符号链接。agent 不需要调用工具查看目录或写入卡片，附加规则不会显示在 Web 的用户消息中。

Web 后端从本轮首个归档头开始捕获，直到该轮成功结束，将中间回答、后续讲解、工具调用与结果按出现顺序合成一张独立 HTML，保存为 `StudyCard/Python语法/容器/list/切片.html`。归档头之前的内容、推理和用户引导不进入卡片。普通工具记录可折叠；`visualize` 调用则替换为实际展示内容：HTML 使用隔离的内嵌 iframe，Markdown 转为排版正文，图片嵌入为 data URI，组件参数保留归档时的快照。卡片不依赖 Web 服务或原始项目文件，下载后可在浏览器独立打开；组件可继续在本地交互，参数变化不回写归档文件，组件提问仅显示为文字。公式使用原生 MathML，不依赖在线脚本或字体。

同名文件自动使用 `切片-2.html`、`切片-3.html`，也避开旧 Markdown 卡片的同名位置，不覆盖已有内容。路径必须在卡片目录内，路径段与卡片目录不接受符号链接。没有归档头、失败或中断的轮次不保存。代码块和引用中的归档头示例不会启动捕获。归档头错误、路径无效、快照丢失或写入失败时，会在该轮下方显示原因，原会话仍保留，不会自动改写或补生成卡片。捕获的文本和工具记录合计最多 4 MiB / 2000 项，合成后 HTML 最多约 32 MiB，超限明确报错，不保存截断内容。

保存结果显示在回复下方，可点击链接打开卡片，也可以通过现有文件栏展开 `StudyCard/`、点击 HTML 卡片直接预览，并切换查看原文。保存后刷新已打开的目录列表。HTML 卡片在隔离 iframe 中运行；普通 HTML 文件继续显示为原文。浏览器关闭不影响后端继续归档，后端必须仍在运行。最近 30 条归档结果随会话恢复显示，更早的卡片继续保留在磁盘中。已有 Markdown 卡片不迁移，仍可照常阅读。

`/StudyCard --stop` 从下一轮生效，已开始的轮次沿用开始时的状态。下一轮附加一次“StudyCard 功能已关闭，不再输出归档头”的提示，该轮不再提供目录树或归档；随后停止附加相关提示。关闭提示在 Codex 接受该轮后才消耗，发送被拒绝时保留到下一次发送。即使模型继续输出旧的归档头，关闭状态也不会保存。排队消息按实际派发时的开关和目录树处理；引导消息属于当前轮次，不改变其归档状态。

选图通过浏览器读取用户选中的文件，再上传到 Termux 的本地服务，不要求 Termux 获得整个手机存储的读取权限。若所用 Android WebView 没有实现文件选择器，请在系统浏览器打开同一个 localhost 地址。HEIC、GIF、SVG 暂不接受，需要先转成支持的格式。10 MiB / 4 张是本客户端的限制；图片推理还取决于所选模型和服务端的支持。

图片原件保存在数据目录的 `uploads/`（默认 `.data/uploads/`），发送时通过 app-server 的 `localImage` 输入交给 Codex，随后发送给当前模型服务；不会通过第三方图床中转。为保留历史预览，原件不会自动删除；移除草稿附件仅取消本次附加，不删除磁盘副本。手动清理该目录会影响历史预览及尚未发送的图片队列。

更新后端代码后，需要在当前任务结束后运行 `codexwui --stop`，待停止后再运行 `codexwui`，并刷新页面；重启会中断尚未结束的任务，将排队消息保留为未发出。

## `/config` 全局设置

输入 `/config` 或点击顶部 `⚙`，可调整最大同时运行会话数、RAM 保护阈值（MiB）、最大后台进程数、空闲清理等待时间（分钟）、普通附件上限（MiB）、文件展开形式，以及新建主会话的默认模型与推理强度。无需先创建或选择会话；Codex 断线时仍可打开并保存资源配置。模型列表和推理选项来自本机 Codex，设置新的默认模型需要连接可用；已有会话继续使用自己的设置，可通过 `/model` 单独修改。BTW 继续沿用其现有继承规则，不由全局默认模型直接覆盖。

点击“保存设置”后动态应用，无需重启；其他页面通过事件流收到新配置。降低并发额度不会打断已运行任务，只限制新任务。RAM 和进程上限由独立守护进程重新采样、校验并确认，低于当前用量的降低请求会被拒绝，旧设置保留。资源占用仍可能在后续运行中超过预算，届时继续执行原有的整个后端回收保护。Codex 已退出时保存预算不会自动拉起后端，需要 `/reload` 恢复连接。

配置写入数据目录的 `config.json`（默认 `.data/config.json`），使用临时文件与原子替换；写入或应用失败时返回错误，保留上一份配置。优先级为：**保存的配置 > 启动环境变量 > 内置默认值**。面板显示各项来源；设置保存后优先级不会被 `/reload` 继承的旧环境变量覆盖。配置文件在启动时读取，手动改文件后需要重启；运行中请通过面板保存以动态应用。

多个页面编辑时采用版本检查，后保存的旧表单会提示重新读取，防止覆盖其他页面的修改。“重新读取”会用服务端当前配置替换表单。上传中的普通附件沿用上传开始时的上限，新上传和发送校验使用新值；已经上传但超过新上限的附件需要调整上限后才能发送。图片仍保持单张 10 MiB 的独立限制。

首次升级需待当前任务结束后执行一次 `/reload` 并刷新页面，加载新增的后端接口。此后面板内设置可动态修改。端口、数据目录和 Codex 程序路径仍通过启动环境设置，修改后重启。

## 平板上的进程与内存保护

左下角连接状态旁的小号 `RAM 1.2/4G` 显示服务及工具进程的合计 RSS 与实际内存上限（按 GiB 换算）。每 5 秒读取已有采样，页面进入后台时暂停，回到前台立即更新；请求失败、断连或采样过期时用 `--` 表示当前值不可用。

每个 Web 服务通过一个独立 Node 守护进程启动 Codex。守护进程每 500 ms 扫描 `/proc`，跟踪 Codex 的进程树、同一系统会话内的孤儿进程，以及已观察到的另建系统会话的子进程。发信号前对照 PID 与启动时间，不按 `python`、`node` 等进程名批量终止程序。

`npm run setup` 会在已有 C 编译器和 Node 头文件可用时，编译一个很小的 Node 原生模块到 `.data/runtime/`。它使用 Linux/Android 的 subreaper 功能，让守护进程接收父进程已经退出的派生程序，覆盖“另建系统会话且在首次扫描之前失去父进程”的情况，并回收退出后的僵尸进程。不新增后台进程，不自动安装编译器。无法编译或系统不支持时，仍可使用扫描回收；`/status` 和 `codexwui --status` 会显示孤儿进程回收是否已启用。

关闭服务或初始化失败时，先关闭 Codex 的 stdin，随后依次发送 `SIGTERM`、`SIGKILL`，等待并再次扫描残留。Web 服务意外退出时，守护进程继续清理；守护进程意外退出且 Web 服务仍存活时，Web 服务接手清理。`codexwui --stop` 会等待退出并检查自己记录的进程树，未确认回收完成时返回失败。

默认预算如下。可通过 `/config` 动态调整，或在启动前通过环境变量提供初始值（均需为正整数）；已保存的配置优先于环境变量。运行中修改启动环境变量仍需重启。

| 设置 | 默认 | 作用 |
| --- | --- | --- |
| `CODEXWUI_MAX_ACTIVE_TURNS` | `2` | 同时运行的主会话上限；超过时拒绝新任务并保留浏览器草稿 |
| `CODEXWUI_MAX_PROCESSES` | `48` | Codex 及其被跟踪派生进程的数量上限，不含 Web 服务与守护进程 |
| `CODEXWUI_MAX_RSS_MB` | `4096` | Web 服务、守护进程、Codex 及被跟踪进程的 RSS 合计上限，单位 MiB（4 GiB） |
| `CODEXWUI_IDLE_MINUTES` | `5` | 整个会话及子代理均空闲后，清理后台终端并取消订阅的等待时间 |

也可以在启动时显式指定内存预算：

```sh
CODEXWUI_MAX_RSS_MB=4096 codexwui
```

达到进程或内存预算、启动任务的 RPC 超时而结果无法确认、或后台清理失败时，会停止并回收整个 Codex 后端，包括其他运行中的会话。页面会显示原因，Follow-up 队列暂停；需要重启服务恢复连接，重启后 Follow-up 保留为未发出，预引导仍会清空。保护不会撤销已经写入的项目文件。

正常关闭网页或切换会话仍不停止工作。失败/中断任务会及时清理后台终端，成功任务的后台终端最多保留到空闲期限。因此，任务结束后留下的开发服务器、预览或 watch 进程也会被空闲清理；需要保留更久时增大 `CODEXWUI_IDLE_MINUTES`。取消订阅后的 MCP/线程资源何时卸载仍由 Codex 管理，官方目前有 30 分钟空闲宽限期，并非五分钟时立即杀掉所有 MCP。[官方 App Server 生命周期说明](https://learn.chatgpt.com/docs/app-server)

Web 后端的工具/消息项缓存总预算为 16 MiB，每轮最多 100 项、每个会话保留最近 4 轮；空闲释放时清除对应缓存，历史继续从 Codex 读取。单条协议消息超过 8 MiB 时会回收后端，避免超大工具结果或历史响应撑爆进程。

这是无需 root 的保护，无法保证避免所有 Android 系统级 OOM。RSS 合计会重复计入共享页，阈值属于保守保护预算；每次采样之间的突发分配、Web 与守护进程同时被系统杀掉，无法保证回收。在原生模块未启用的扫描模式下，未被观察到就脱离系统会话并失去父进程的程序也无法保证回收。旧版本已经遗留、没有归属记录的进程不会按名称自动清理。

右栏标签支持鼠标、触屏与键盘：点击立即切换；标签获得焦点后，`←` / `→` 只移动焦点，`Enter` 进入对应标签。选中背景表示正在显示的标签，焦点边框表示键盘当前位置。文件标签过多时可横向触屏滑动或使用滚动条，键盘焦点也会自动滚入可见区域。

目录区域获得焦点后，`↑` / `↓` 选择条目，`→` 或 `Enter` 进入文件夹 / 打开文件，`←` 返回上级（项目根处不继续返回）。返回上级后选中刚离开的文件夹。目录或原文区域按 `Shift+Tab` 回到文件标签栏；文件标签上按 `Delete` 可关闭该标签。方向键只在这些区域生效，不占用聊天输入框的按键。

文件面板中的 Markdown 默认显示原文，可用“渲染”开关查看排版和公式；HTML 默认开启渲染，关闭开关查看只读源码。聊天中的文件链接继续打开 localhost 独立预览页，两处使用相同的 Markdown 渲染器。HTML 预览仅加载自包含的内联样式、脚本和嵌入资源，不加载外部或相对路径资源；源码及 Markdown 超过 1 MiB 时只显示开头部分，下载可获取完整文件，HTML 完整预览上限为 33 MiB。

“目录”标签右侧的“↑ 上传文件”打开安卓文件选择器，可多选文件并复制到当前浏览的项目目录，手机原文件保留。上传目标在打开选择器时确定；上传中切换项目或目录不会改变目标。文件按顺序上传，显示进度并可取消，已经完成的文件保留；上传完成后刷新目标目录并选中最后上传的文件。同名文件自动另存为 `文件名 (1).扩展名`，不会覆盖原文件。单个文件上限沿用 `/config` 的普通附件设置（默认 100 MiB），在上传开始时固定；中断、超限或目标目录变更时清理临时文件。文件直接保存到工作区，不会附加到聊天或自动发送给模型。

页面会检查后端是否提供工作区上传能力。更新前端文件后若服务仍运行旧代码，上传按钮会暂停使用并提示 `/reload`，也可在当前任务结束后点击“重载服务”；重载会保存草稿、停止运行中的任务，恢复后需要重新选择文件。若请求中才发现接口缺失，会停止整批上传并显示同样的提示。

文件工具栏提供“展开 / 收起”，默认填满整个工作区面板；`/config` 中的“文件展开形式”可改为类似可视化组件的全屏浮层，保存后动态生效。展开与收起保留当前阅读器和渲染内容；在文件面板内按 `Esc` 可收起。顶部 `☰` 和列表内的收起按钮可展开、收起左侧会话列表；收起列表后，打开的工作区面板与对话区各占页面宽度的 50%。在较窄窗口重新展开会话列表时，会先关闭工作区浮层，便于选择会话。

PDF 使用随应用提供的 PDF.js 在本机阅读，支持翻页、页码跳转、缩放、适应宽度及密码输入；只绘制当前页并限制画布像素数，切走后释放阅读器。工具栏提供“浏览器打开”和下载：Android 上尝试唤起 Edge，未安装时使用普通本地链接；已经在 Edge 或桌面端时直接打开本地 PDF。外部应用唤起取决于浏览器和系统设置，本地链接需要在运行服务的同一台设备上访问。

## 实现

```text
手机浏览器 → localhost Node HTTP/SSE → Node 守护进程 → codex app-server（stdio）
                                                         └→ 本机项目、工具与子代理
```

使用小型版本匹配的 app-server 客户端，而非 TypeScript SDK 的单任务封装。此选择用于支持审批、历史分页、steer、技能和子代理关系；官方同样推荐自定义富客户端采用 [app-server](https://learn.chatgpt.com/docs/app-server)。模型选择通过 `model/list` 读取目录，以 `thread/settings/update` 设置当前会话的后续任务，不修改全局配置文件。本机开发与验证基于 `codex-cli 0.160.1`，其他版本的实验协议可能不同。

预引导以本机版本实测的 `thread/tokenUsage/updated` 通知作为迭代边界信号，并等待已观察到的并行工具结束。边界触发时同步锁定待投递记录并发送 `turn/steer`；修改/撤回用版本号校验，已提交消息用 `clientUserMessageId` 与 `userMessage.clientId` 对齐。这个通知是外部观察点，不是暂停模型循环的内部钩子，因此不能保证赶上紧接着的下一次模型请求；极端时序下可能晚一轮，或因原任务已结束而拒绝投递并保留内容。界面保留“立即引导”作为主动提交入口。没有收到明确回执的传输失败不会自动重发。

`server/codex.mjs` 处理 RPC 分流与审批，`state.mjs` 保存短期流式状态，`queue.mjs` 管理 follow-up，`steers.mjs` 管理预引导及其提交/回执状态，`git.mjs` 只读调用 Git，`files.mjs` 校验项目边界、预览文件并接收工作区上传，`images.mjs` 限制上传大小、检查图片类型并将附件 ID 转成受控的本地图片路径。`public/` 是无构建步骤的移动端界面，文件面板独立管理焦点和阅读状态，不随聊天流式渲染重建。

`supervisor.mjs` 独立监测进程/内存并处理退出，`processes.mjs` 封装 Linux/Android 的进程身份与回收，`lifecycle.mjs` 管理主会话并发、停止确认、子代理发现和空闲释放，`limits.mjs` 校验资源预算。守护进程额外的内存也计入预算，无需新增生产依赖。

会话历史由 Codex 自身保存；项目列表在 `.data/projects.json`。不读取或复制登录凭据。HTTP 接口校验 localhost Host/Origin，不启用跨站访问。不要把此服务转发到公网。

规划地图见 [.scratch/termux-codex/map.md](.scratch/termux-codex/map.md)，本机协议研究见 [protocol.md](.scratch/termux-codex/research/protocol.md)。

## 开发验证

```sh
npm install
npm run check
npm test
```

生产启动不依赖 npm 包；开发测试使用 jsdom 与 Node 内置测试工具。测试覆盖并发请求分流、跨会话事件、失败后队列暂停、Git 状态/diff、HTTP 边界、技能输入，以及浏览器 DOM 中的切换、steer 与技能交互。jsdom 不做真实浏览器排版，手机真机视觉效果仍以浏览器实际显示为准。

原生 BTW 分叉验证可运行 `CODEXWUI_TEST_CODEX=codex-native node --test test/btw-native.test.mjs`（其他环境将变量设为可用的 Codex 启动器）。该测试使用隔离的临时 Codex 配置和本机模拟模型接口，不调用远程模型；覆盖等待工具结果时分叉、创建时不生成、工具调用配对、只读工具加载、重启恢复及空白主会话。

Markdown、公式与 Mermaid 渲染的浏览器资源随源码保存在 `public/vendor/`，包含上游 MIT 许可证；PDF.js 浏览器资源及 Apache-2.0 许可证也保存在 `public/vendor/pdfjs/`；开发依赖中的 markdown-it / KaTeX / Mermaid / PDF.js 版本由锁文件固定。升级对应依赖后运行 `npm run vendor:rendering` 更新本地脚本、样式和字体，再运行检查与测试；生产启动仍无需 `node_modules`。公式测试覆盖截图中的表格、四类分隔符、流式补齐、代码隔离和不可信内容。

KaTeX 的分数高度、上下标与基线偏移依赖生成的 `style` 属性，因此 HTTP CSP 使用 `style-src-attr 'unsafe-inline'` 允许这些属性，样式表与脚本仍限制为本机来源。Markdown 继续禁用原始 HTML，KaTeX 保持 `trust: false`。jsdom 不执行 CSP，也不做真实排版；HTTP 回归测试会单独校验公式所需样式与实际响应策略，防止分数和下标因内联样式被拦截而错位、裁切。

### 普通文件附件

输入框底部的 `📎` 可以选择文档、文本、代码和压缩包等文件（选择器明确列出常见类型，以兼容 Android 浏览器），每条最多 4 个、默认每个最多 100 MiB；可与图片一起发送，支持只发文件、引导、编辑预引导和排队。上传完成后显示文件名与就绪状态，点击 `×` 移除；切换会话保留各自草稿，刷新会丢失未发送草稿。

普通文件上限可通过 `/config` 动态调整，或用启动环境变量 `CODEXWUI_MAX_FILE_MB` 提供初始值，单位 MiB，环境变量必须是正整数。前端校验、按钮提示、后端上传及发送校验均使用这个配置；图片上传仍单独限制为每张 10 MiB。尚未保存全局配置时，也可以停止后带新环境变量启动，例如改为 200 MiB：

```sh
codexwui --stop
CODEXWUI_MAX_FILE_MB=200 codexwui
```

普通文件边接收边写入磁盘，不在后端内存中积攒整个文件；完成后才发布为可发送的附件。超限、上传中断或写入失败会清理未完成的临时文件。

文件保存在数据目录的 `attachments/`，使用唯一文件名避免覆盖。发送时将受控的本机绝对路径交给 Codex，由它使用本机工具读取；上传成功不代表已解析 PDF、Office 或压缩包，具体格式取决于可用工具与会话读取权限。聊天界面只展示附件文件名；发送给 Codex 的消息仍保留实际路径供读取。附件不会自动删除，移除草稿不会删除磁盘文件。

### BTW 侧聊

在主输入框输入 `/btw 问题`（也支持 `/BTW`），会创建一个新侧聊并提问；单独输入 `/btw` 或点击「新侧聊」会创建一个空白侧聊。点击 BTW 标签打开上次选中的侧聊，通过下拉列表切换。同一主会话可以拥有多个不同时间创建的侧聊，各自保存草稿、回答和运行状态，可以继续追问、单独停止。侧聊回答下的「带回主会话」会追加到主输入框，检查后再发送；不会自动引导或打断主任务。

BTW 与主输入框共用附件上传和消息展示逻辑。可选择文件、图片，也可粘贴或拖入附件；支持只发附件，用 `Ctrl+Enter` 或 `Cmd+Enter` 发送。每条消息最多 4 张图片和 4 个文件，图片类型与大小、文件大小限制沿用主会话。上传状态、缩略图、移除按钮、失败提示及发送失败后的草稿保留方式一致。各个侧聊的附件草稿独立，切换侧聊不转移上传中的附件。引导、排队和引导编辑均保留附件；编辑引导时可移除附件。完成上传的附件草稿随 `/reload` 恢复。

侧聊回答期间，输入框支持选择「引导（steer）」或「排队（follow-up）」。引导复用主对话的预引导机制，在执行边界提交；提交前可修改、撤回，也可以点击「立即引导」。排队消息在当前回答成功完成后依次发送，失败或停止转为未发出，可撤回修改、删除、继续单条或继续全部。预引导与队列分别属于各个侧聊，切换、刷新网页或断线重连会恢复；Web 服务重启后队列保留为未发出，预引导会清空。排队启动的新轮次继续使用 BTW 的只读策略。

创建时使用本机 Codex 的 `thread/fork` 固定当时的对话上下文，后续不会自动同步主会话的新消息。主会话运行中的轮次在副本中记录为中断，由 Codex 处理未完成的工具调用；主会话继续运行。继承历史供模型参考，侧聊面板只显示分叉后的提问和回答。创建分叉不启动模型生成，并禁止继承目标自动续跑；点击发送才开始新一轮生成。主会话尚无消息时先只保存 CodexWUI 侧聊记录，首次发送时创建空白 Codex 线程，仍不带入后来新增的主会话内容。对应关系写入数据目录的 `btw.json`，重启服务后可继续；未发送草稿只保留在当前页面内，使用 `/reload` 时会恢复。旧版侧聊记录会保留；旧版从未持久化的侧聊无法恢复原上下文，需要创建新侧聊。

BTW 可以联网搜索，并通过专用的本地 MCP 工具列出项目目录、读取 UTF-8 文件。项目外只允许读取用户明确附加到此侧聊的文件，授权随侧聊记录保存；不能借附件路径读取其他侧聊的项目外附件或任意本机文件，符号链接仍受目录边界校验。图片直接随消息交给模型；二进制附件可上传，专用文本读取工具不解析 PDF、Office 等二进制格式。请求 `read-only` / `never` 权限，关闭继承的 MCP、可配置的命令、插件与代理功能，并提示模型把修改建议交回主会话。模型内置工具可能不完全遵循这些开关，且 Termux 不支持 Linux 沙箱，因此这不是独立的强隔离安全环境。BTW 与主会话共享后端及并发额度；关闭面板不会停止回答。

更新后首次使用，需要在当前任务结束后重启服务：`codexwui --stop`，再运行 `codexwui`。

### `/reload` 重启后端

在主输入框输入 `/reload`，或从 `/` 命令菜单选择 reload。页面会保存当前标签页中的主会话与 BTW 草稿，通知后端清理 Codex 及其子进程，再由独立重启助手等待旧服务退出并启动新服务。前端确认新服务已恢复后自动刷新；重复请求不会重复启动。Codex 断线时也可以使用该命令，只要 Web 服务仍可响应。

重启作用于整个服务，会停止所有主会话、BTW 和子代理，将排队消息持久化为未发出，并清空内存中的预引导；已保存的会话历史不受影响。完成上传的草稿附件会恢复，未完成的上传需要重新选择。等待超时会在页面提示，可检查数据目录中的 `server.log`。端口、数据目录和环境设置沿用当前服务；原来以前台方式启动的服务重启后将转为后台运行。

首次升级到包含 `/reload` 的版本，旧进程尚未加载重启接口，需要先手动执行一次 `codexwui --stop` 和 `codexwui`。

### 对话内展示：`visualize`

主会话中的 agent 可以调用 `visualize`，把交互 HTML、Markdown 文档或图片直接放在对话流中。界面默认只显示内容卡片，隐藏该工具的名称、参数和返回 JSON；其他工具继续按原方式展示。可以直接要求“用 visualize 做一个可调参数的轨道模拟器”或“用 visualize 展示这份 Markdown / 图片”。新会话和历史会话在下一次发送任务时均可使用，不需要手动注册工具。

工具接受以下形式；HTML、Markdown 可提供 `content` 或项目内 `path`，图片需要 `path`。`md` 是 `markdown` 的别名，`title` 可选。

```js
visualize({ type: "html", title: "轨道模拟", content: "<!doctype html>..." })
visualize({ type: "markdown", path: "reports/analysis.md", title: "分析报告" })
visualize({ type: "image", path: "plots/orbit.png", title: "地面轨迹" })
```

HTML 在隔离 iframe 中运行，支持自包含 CSS、JavaScript、Canvas、SVG 和内嵌数据。默认禁止外部脚本、网络请求、嵌套 iframe、父页面访问及 localStorage；需要库或数据时应内嵌。HTML 和 Markdown 每份最多 1 MiB；图片支持 PNG、JPEG、WebP、GIF、SVG，每张最多 10 MiB。Markdown 使用现有公式与排版规则，原始 HTML 不执行，图片单独展示并可点击打开原图。

内容卡片支持展开、收起和重新运行 / 加载。后续文字、工具事件和同步更新不会重建已挂载的 iframe；切换会话返回或刷新后重新加载保存的内容。每次调用保存独立快照，后续修改或删除原文件不影响已发布版本。快照和组件参数保存在 Web 数据目录的 `visualizations/`，服务重启后保留，不自动删除。HTML 的相对外部资源不会自动打包，应发布自包含文件。

生成页面可使用以下小型桥接 API 保存参数并恢复，状态必须是最多 64 KiB 的 JSON；不使用它的页面在重新加载后恢复初始状态，动画运行进度和任意 JavaScript 内存不会自动保存。

```js
addEventListener("codexvisualizeready", () => {
  const saved = window.codexVisualize.getState();
  // 用 saved 恢复控件；随后每次参数变化时保存：
  // window.codexVisualize.setState({ height: 550, inclination: 53 });
});
// 将文字或当前参数摘要放入主输入框，由用户检查后发送：
// window.codexVisualize.sendMessage("根据当前参数解释：...");
```

滑块、按钮等本地交互不调用模型；模型也不会自动看到 iframe 当前画面或参数，需要通过后续文字明确带入。页面隐藏时会收到 `codexvisualizevisibility` 事件，`event.detail` 为可见状态，页面可据此暂停动画。

后端通过每个主会话的本地 stdio MCP 服务提供工具，沿用已有进程预算与生命周期，不写全局 Codex 配置、不新增生产依赖。每轮附加工具使用说明，浏览器隐藏该内部说明；BTW 不提供发布工具，分叉继承的主会话发布调用也会被拒绝。首次更新后，待当前任务完成再使用 `/reload` 重启服务并刷新页面，即可加载此功能。


### Agent 跨进程交流：agentctl + skill

`npm run setup` 安装 `agentctl` 命令和 `agent-chat` 技能（位于 `${CODEX_HOME:-~/.codex}/skills/agent-chat`）。CLI 连接已有 CodexWUI，输出 JSON 后退出，不启动常驻进程。可通过 `$agent-chat` 调用技能，`agentctl --help` 查看完整语法。

```bash
agentctl '~/codex' list
agentctl '~/codex' create --model MODEL --reasoning high
agentctl '~/codex:1' call --message-file ./prompt.md
agentctl '~/codex:1' call --message '调整当前任务方向' --steer
agentctl '~/codex:1' observe --message-id MESSAGE_ID
agentctl '~/codex:1' stop
agentctl '~/codex:1' fork
agentctl '~/codex:1' btw --message '解释这个设计'
```

工作区路径会展开 `~` 并解析软链接。主线程使用递增编号，子代理为 `1.sub1`，侧聊为 `1.btw1`。首次发现历史线程时按创建时间编号，之后编号不变且不复用；映射与计数器保存在 `agents.json`。简写 `1` 使用调用者当前工作目录。`create` 创建空白主线程，`fork` 创建继承历史的独立主线程，`btw` 创建只读侧聊；未附消息时不启动生成。服务没有代建子代理的操作。

默认 call 是 follow-up，空闲时开始、忙时排队；`--steer` 直接引导当前轮，空闲时明确报错。回执表示已经收件，不能当作完成。`observe` 返回一次状态与最近 20 轮主线程历史，可用 `--cursor` 分页；BTW 返回最近侧聊历史。`--message-id` 查询消息状态、是否被 UI 修改或删除以及对应 turn；`--reply-to` 关联回复，回复需要显式发给原发送者，不会自动唤醒。

文本与 `--message-file` 二选一。文件按调用者工作目录读取 UTF-8 正文，最多 200000 个 UTF-16 代码单元、文件最多 800000 字节，超限明确失败；BTW 的来源标记也计入后端长度限制。接收后保存正文快照，回执包含原文 UTF-8 字节数及 SHA-256。调用者路径仅用于来源展示，服务端不自行读取该路径。消息在 UI 显示来源，编辑后回执的哈希与 modified 标记相应更新。

默认连接 `http://127.0.0.1:4310`，可用 `PORT`、`AGENTCTL_URL` 或 `--url` 选择本机服务，默认超时 15 秒。超时或断线不自动重试：先观察目标队列和历史，避免重复发送。服务端以同一本机用户为信任边界；`CODEX_THREAD_ID` 用于来源归属，不是隔离同一用户恶意进程的身份认证。

当前控制范围是连接的 CodexWUI 所管理的会话。其他独立 CLI 的历史可以被发现和观察，不能凭 UUID 接管它正在运行的进程。`list` 的 `operations` 表明可用操作；原生子代理是否接受直接输入取决于后端能力。BTW 保留只读工具策略，不能主动调用交流接口。首次升级请在当前任务结束后使用 `/reload` 加载新后端。

### 上下文用量与会话权限

输入框上方显示当前会话的上下文占用；点击查看最近回报的 token / 窗口容量、累计输入（含缓存）与输出（含推理）。占用按最近一次请求的 totalTokens / modelContextWindow 计算，不包含未发送草稿，也不代表自动压缩阈值。未知数据显示 `—`，离线显示上次快照；收到新的回报后更新。最多保留最近 1000 个会话的用量快照，浏览器刷新及服务正常重启后可恢复；尚未被 Web 服务观察到的历史用量需要等待下一次引擎回报。每个会话单独统计，不合并子代理与 BTW。空闲主会话可在详情中请求压缩。

顶部入口按 **Model / Reasoning / Authority** 显示；点击或输入 `/model` 可修改当前会话。Authority 选项为默认（使用本机 Codex 配置）、只读、工作区、完全访问。只读与工作区在需要额外权限时询问；完全访问解除沙箱限制并使用 `never` 命令审批策略。实际可用权限仍受 Codex 的配置约束。修改使用 `thread/settings/update`，从后续轮次（含排队消息）生效，运行中的任务和 steer 保留当前轮设置。选择「默认」时重新读取本机项目配置。显式权限选择在会话卸载、服务重启后恢复。

`/config` 的「会话初始权限」只用于之后新建的主会话，默认值为「默认」。修改不会覆盖已有会话、继承来源的分支会话或 BTW 的只读限制。
